## 6. Questions a PC member is likely to ask, with suggested answers

1. **"Isn't refined ≈ oracle true by construction, since the simulated user returns the exact omitted fragment?"**
   Largely yes, and the paper says so (l. 363–366). The non-trivial findings are three:
   - Detection was exact: 360/360 omitted dimensions found, no false positives, and no questions at k = 0.
   - The rewritten request, produced by an LLM from fragments, preserves the ranking up to the pipeline's own run-to-run noise.
   - Without clarification, agreement collapses already at k = 2 (J5 0.15).

   The imperfect-user series tests behaviour the oracle cannot test (opt-out, vague answers).
2. **"What does the EVPI ordering buy over a fixed order?"**
   With uniform weights the score is $1-1/n$, so it mainly puts option-bearing questions (location, use) before open ones, and the redundancy penalty defers re-asking after a vague answer. No ablation against a fixed order was run. The honest claim is "SAGE-style ordering adopted", not "better ordering" (M5).
3. **"Why no static-form baseline or user study?"**
   Both are stated as limitations (l. 677–680). The demo lets attendees act as real users, but no measurements are claimed from that.
4. **"Is the oracle ground truth?"**
   No. It is a reference query output whose own repeats agree at J5 0.87. The paper says this three times (l. 327–328, 392–393, 678–679).
5. **"Do results depend on one model and one execution?"**
   Yes: one model (Claude Haiku 5.5, CLI default sampling), one execution per series. The two series give different oracle ceilings for the same queries (0.87 vs 0.93), which is why values are compared only within a series. Other-model series exist in the repository but use other datasets or scenarios and are not reported (audit l. 125–137).
6. **"What happens if an attendee declines the location or the use?"**
   The code supports it (`NO_PREFERENCE` → `NOT_REQUESTED` for any dimension; declining $L$ means no geographic filter), but it is not covered by the reported runs. The presenter should steer opt-outs to preferences (M3).
7. **"Can I reproduce the runs?"**
   The code, scenarios, analysis scripts and all 569 per-run records are in the repository. The metrics reproduce exactly from `runs.jsonl` (§4). Re-running requires rebuilding the property table from the Piedmont APE open data; the table is not distributed, but its hash is recorded (m7).
8. **"What do attendees do if the Wi-Fi or provider fails?"**
   The offline scenario mode replays completed runs with no network. It must be configured to the reported series before the conference (M1).
9. **"Is Italian input supported?"**
   No. The dialogue and the rewrite are forced to English (`service.py:855`), and the paper says "in English" (l. 235).
