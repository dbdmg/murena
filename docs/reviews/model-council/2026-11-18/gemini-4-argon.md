## 6. Questions a PC Member Is Likely to Ask, with Suggested Answers

### Q1: Why use a multi-turn natural-language dialogue instead of a simple 6-field web form with checkboxes for "No preference"?
- **Suggested Answer:** A static 6-field form forces users to map their domain objective onto MURENA's internal schema upfront. In practice, institutional users start from an unstructured narrative blending some constraints (e.g., *"an existing school building in Turin near green spaces for a nursery"*) while leaving others unstated, or using terms that are ambiguous with respect to the database (e.g., a landmark without a city, or qualitative building terms). Conversational MURENA parses what is already specified in free text, leaves those dimensions untouched, asks only about the unresolved dimensions with context-grounded examples (e.g., matching regulatory uses or plausible cities), handles vague answers via targeted follow-ups rather than forcing a rigid dropdown, and synthesizes a single natural-language prompt $\hat{q}$ for human review before running the unchanged MURENA multi-agent pipeline. We explicitly acknowledge in Section 5 (*Scope*) and Section 6 (*Conclusion*) that our benchmark measures the value of recovered information rather than dialogue vs. a static form, and identify a form-based human-subject baseline as our next step.

### Q2: If omission questions have no enumerable alternatives (`alternatives: []`), what is the SAGE-Agent EVPI score actually doing during question selection?
- **Suggested Answer:** As stated in Section 3 (*Question selection*), our adaptation of SAGE-Agent is purely an *ordering heuristic*, not a stopping criterion or a calibrated posterior. In our implementation (`service.py:635-649`, `uncertainty.py:30-65`), ambiguity questions with $m$ enumerable options (such as location disambiguation over candidate cities) receive uniform weights $1/m$ and positive EVPI ($1 - 1/m$), whereas open-domain omission questions receive a placeholder viability $\epsilon$ (`evpi = 0.0`). Consequently, blocking ambiguities with enumerable alternatives are naturally prioritized first, followed by unconfirmed omissions in canonical template order ($I, D, L, C_b, C_e, C_p$), while the redundancy penalty ($-\lambda \cdot \text{count}$ with $\lambda = 0.5$) pushes any dimension that just received an unclear answer behind not-yet-asked dimensions before cycling back for a rephrased follow-up. Readiness is strictly governed by dimension states (no open `UNCONFIRMED_ABSENT`, `MISSING_CRITICAL`, or blocking `AMBIGUOUS`), never by an EVPI threshold.

### Q3: Why does the inherited proximity agent still apply a university proximity filter in 10 student-residence opt-out runs after the user explicitly declined $C_p$? Is that a bug in the clarification stage?
- **Suggested Answer:** It is a property of the loosely coupled interfaces between the conversational wrapper and the inherited MURENA pipeline, which we intentionally report transparently (`edbt-paper-template.tex:418-420`). The clarification stage works purely at the query-text level: when the user declines $C_p$, the clarifier records `Cp = NOT_REQUESTED` and omits any proximity clause from the rewritten prompt $\hat{q}$ (verified in all 105/105 opt-out runs). However, only the confirmed text $\hat{q}$ is passed to the unchanged MURENA pipeline (Fig. 1). In those 10 `UC08` runs, MURENA's inherited `ProximityAgent` reads the intended use (*"university student residence"*) in $\hat{q}$ and autonomously infers an `education_score` proximity filter. Because our architectural contribution deliberately avoids modifying the inherited MURENA agents or passing out-of-band state masks, we count and report those 10 cases as downstream agent inferences rather than hiding them.

### Q4: Your evaluation relies on a single model (Claude Haiku 5.5) and simulated users over 8 base intents. How sensitive is the clarification stage to user phrasing or different LLMs?
- **Suggested Answer:** While eight base intents is a small cluster count (making $p = 0.008$ the smallest attainable two-sided sign-flip $p$-value, which we report explicitly alongside cluster-bootstrap CIs), each intent is tested across all omission levels $k=0\dots5$ with 3–5 repetitions (304 cooperative runs + 265 imperfect-user runs = 569 runs total). Crucially, the $k=0$ control condition ($q_0$ vs. $q^*$) tests surface-form sensitivity directly—for example, *"capacity for 45 people"* across six sentences vs. *"for 45 children"* in one sentence—and shows that $J_5$ at $k=0$ ($0.87$) matches the oracle's own run-to-run noise ceiling ($0.87$). Furthermore, to facilitate larger multi-model robustness studies beyond a 4-page demo paper, we release the deterministic v4 generator (`scenarios_v4/`, 8,192 scenarios crossing all 256 omission masks with domain-tailored vague and opt-out phrasings).

### Q5: In a busy conference demo session, a 17–38 s dialogue plus a 72–83 s analysis is ~1.5–2 minutes per query. How will you keep multiple attendees engaged at the booth, and what if the venue Wi-Fi or LLM API drops?
- **Suggested Answer:** We designed the demonstration around two complementary modes that can run simultaneously or serve as an instant fallback:
  1. **Live Interactive Mode:** While an attendee types a custom request and steps through the 17–38 s turn-by-turn clarification (which is interactive at ~5–8 s per turn), the presenter uses the live dimension-state table ($I, D, L, C_b, C_e, C_p$) and during the ~75 s downstream multi-agent execution shows the real-time `/processing/:runId` agent trace (Phase 1 parallel extraction, Phase 2 SQL generation and relaxation, Phase 3 scoring).
  2. **Zero-Latency Offline Mode (`DemoPanel` + `/benchmark`):** Pre-loaded with completed benchmark runs, local estate geometries, and precomputed top-10 evaluations, this mode runs 100% locally in the browser without network or LLM calls. Attendees can switch across the 8 regulatory use cases and omission levels $k$, step through the recorded dialogues and editable review prompts, and compare one-shot vs. refined vs. oracle SQL queries and map rankings instantaneously—even if the conference Wi-Fi or external LLM API fails completely.
